# M0 — Foundations

Done in the first build session.

- Repo scaffold: Next.js 16.4 (App Router, Turbopack), React 19.3, TypeScript 6.0, Tailwind 4.3, pnpm 10.
- Env validation (`src/env`), DATA_DIR layout and atomic file helpers (`src/lib/files.ts`), pino logging.
- SQLite (better-sqlite3 13, WAL) + Drizzle schema for projects, assets, products, talent, outfits, campaigns, shots, generations, candidates, reviews, edits, timelines, exports, presets, claude_runs, jobs, job_events, ledger, settings, ui_state, doc_revisions, upload_cache. Migrations in `drizzle/`, applied programmatically at worker boot.
- Job queue (`src/queue`): atomic claim, per-lane concurrency, heartbeats, stale sweep (full sweep at boot), retry/backoff, permanent errors, cancel flag, checkpoints, idempotency keys, SSE event tail. Separate worker process (`worker/main.ts`).
- Design tokens, primitives, app frame, command palette, project switcher.
- Tests: domain, compiler, queue integration, cloud client (msw), CLI parser. `pnpm test` → 28 passing.

Deviations from PLAN.md noted:
- Engines widened to Node ≥ 22.12 (<27); `.npmrc` sets `engine-strict=false` because jsdom pins a newer 22.x patch than some machines carry.
- `shadcn` CLI could not reach its registry from the build environment, so primitives are hand-written on the unified `radix-ui` package (same API surface).
- App code lives under `src/app` (not a top-level `app/`), matching the `@/` alias.
- The worker is run with `tsx` in production (`pnpm start`) instead of a `tsc` emit to `dist/`: TypeScript does not rewrite `@/` path aliases or add ESM extensions, so the emitted JS was not runnable under Node. `tsc -p worker/tsconfig.json` still typechecks the worker during `pnpm build`.
- Fonts for ffmpeg `drawtext` are vendored as TTF in `assets/fonts/` (Inter, Instrument Serif; both SIL OFL) because the fontsource packages only ship woff/woff2.
